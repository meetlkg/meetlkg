02 / HOW I THINK ABOUT SYSTEMS

The model is one
part of the system.

My approach starts with the work to be done.
Explore the four questions I bring to an agent system.

01

Start with an outcome.

Define the task, its boundaries and what completion looks like. The workflow should make sense before choosing how much autonomy to add.

IN MY WORK

LaunchAI: product direction for accounts payable and ERP-connected finance workflows.

02

Design the context, not just the prompt.

Decide what belongs in each step, what carries forward and when the system needs new information. Context continuity is part of the architecture.

IN MY WORK

Plena: context engineering for task continuity across self-serve multi-agent workflows.

03

Make the actions explicit.

Tools, interfaces and guardrails shape an agent’s behavior. I approach them as product and engineering decisions that need clear boundaries.

IN MY WORK

LaunchAI: standards for MCP servers, tool/function calling and deterministic agent workflows.

04

Measure the work, not only the response.

Model benchmarks are one signal. Task outcomes, traces and observable behavior help reveal whether the whole system is doing useful work.

IN MY WORK

LaunchAI: SLM/SVLM evaluation strategy, benchmarking, agent tracing and LLM observability.
